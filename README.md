## 为什么需要 EvoForge？

现在的 AI Agent 已经能写代码、改文档、查资料、跑命令、操作浏览器，但它们经常有几个明显的问题：

- **一次性太强，连续性太弱**  
  今天做完一轮，明天又要重新解释上下文。

- **会聊天，但不像一个真正的工作台**  
  文件、终端、Git、浏览器、记忆、技能、权限、计划往往散落在不同地方。

- **能执行任务，但不够可控**  
  长时间运行时，权限边界、确认机制、审计记录都很重要。

- **能解决问题，但经验很难沉淀**  
  一个复杂任务里踩过的坑，下次还可能重新踩一遍。

**EvoForge 想解决的是这个问题：**

```text
把 AI Agent 变成一个能长期协作、能积累经验、能安全调用工具的桌面工作台。
```

它不是普通聊天框，也不是单纯的代码编辑器插件。EvoForge 更像是一个本地 Agent 操作系统：你给出目标，它负责计划、执行、验证、恢复上下文，并在必要时向你确认。

## 快速开始

### 1. 下载并安装

打开 [Releases](../../releases)，下载适合你系统的安装包。

### 2. 配置模型服务

首次启动时，EvoForge 会引导你配置模型服务。你也可以手动编辑：

```text
~/.evoforge/config.toml
```

示例：

```toml
default_provider = "openai_compatible"

[providers.openai_compatible]
base_url = "https://api.example.com/v1"
api_key = "sk-..."
model = "your-model-name"
```

你可以使用 OpenAI-compatible、Anthropic、DeepSeek、Qwen、Gemini、OpenRouter、Ollama 等模型配置。实际支持项以应用内设置页为准。

### 3. 开始一个目标

你可以直接告诉 EvoForge：

```text
帮我检查这个项目，修复构建错误，并跑一遍测试。
```

或者：

```text
围绕这个仓库长期运行：理解架构、找出问题、分批改进，并每步验证。
```

EvoForge 会根据当前工作区、工具权限和模型配置来拆解任务、执行工具、汇报进展。

## 设计理念

### 1. Agent 应该围绕目标工作，而不是围绕单轮问答工作

复杂任务很少能在一轮对话里完成。EvoForge 的核心是长期目标、任务计划、状态恢复和验证闭环。

### 2. 记忆应该克制，技能应该可复用

不是所有历史都应该变成记忆。EvoForge 区分：

- **记忆**：稳定偏好、项目事实、长期有用的信息
- **会话搜索**：临时过程、历史决策、某次任务上下文
- **技能**：可复用的方法、流程、领域知识和工具使用经验

### 3. 能力越强，权限越要清楚

一个能写文件、跑命令、操作 Git 和浏览器的 Agent 必须有边界。EvoForge 把权限策略、用户确认、沙箱和审计记录作为核心能力，而不是事后补丁。

### 4. 桌面应用应该服务真实工作流

EvoForge 优先支持本地工作区、文件、终端、GitHub、浏览器、MCP 和长期运行。它不是纯网页聊天，也不是只服务 demo 的玩具。

## 安全与隐私

EvoForge 默认使用本地文件存储：

```text
~/.evoforge/
├── config.toml          # 模型服务与应用配置
├── mcp.json             # MCP 服务配置
├── sessions/            # 原始会话记录
├── memories/            # 记忆
├── skills/              # 技能
└── reflect-log.jsonl    # 反思与审计记录
```

| 机制 | 说明 |
|------|------|
| 本地优先 | 会话、技能、记忆和配置默认保存在本机。 |
| 权限确认 | 高风险工具调用会根据策略请求确认。 |
| 沙箱限制 | 终端和文件工具受工作区与 OS 级边界约束。 |
| 审计记录 | 反思、记忆和技能候选保留可追溯记录。 |
| 模型可选 | 你可以按自己的隐私和合规要求选择模型服务商。 |

> 模型请求会发送到你配置的模型服务商。请避免把敏感数据发送到不受信任的模型服务。

## 当前边界

EvoForge 仍在快速迭代中。不同平台的打包、签名、自动更新、模型兼容性和浏览器能力可能随版本变化。

如果你把 EvoForge 用在重要工作流中，请先在非关键项目里验证工具权限、模型输出质量和沙箱策略。
