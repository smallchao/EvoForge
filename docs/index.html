为什么需要 EvoForgeWhy EvoForge

现在的 AI Agent 很强，
但有四个老问题Today's AI agents are powerful,
but share four old problems

🔁

一次性太强，连续性太弱Strong in one shot, weak in continuity

今天做完一轮，明天又要重新解释上下文，长期任务无从谈起。Finish a round today, re-explain everything tomorrow. Long-term work never compounds.

💬

会聊天，但不像一个真正的工作台A chat box, not a real workbench

文件、终端、Git、浏览器、记忆、技能、权限、计划往往散落在不同地方。Files, terminal, Git, browser, memory, skills, permissions and plans live scattered across tools.

🎛️

能执行任务，但不够可控Executes tasks, but with little control

长时间运行时，权限边界、确认机制、审计记录都很重要——却常常缺席。In long-running sessions, permission boundaries, confirmations and audit trails matter — yet are often missing.

🕳️

能解决问题，但经验很难沉淀Solves problems, loses the experience

一个复杂任务里踩过的坑，下次还可能重新踩一遍。Pitfalls hit in one complex task get hit all over again the next time.

设计理念Design Philosophy

四条原则，贯穿始终Four principles, applied throughout

01

围绕目标工作，而不是围绕单轮问答Work around goals, not single turns

复杂任务很少能在一轮对话里完成。核心是长期目标、任务计划、状态恢复和验证闭环。Complex work rarely fits one conversation. The core loop is long-term goals, plans, state restoration and verification.

02

记忆应该克制，技能应该可复用Memory should be restrained; skills, reusable

不是所有历史都应该变成记忆。EvoForge 严格区分三层：Not all history deserves to become memory. EvoForge separates three layers:

记忆 = 稳定事实Memory = stable facts 会话搜索 = 历史过程Session search = past process 技能 = 可复用方法Skills = reusable methods
03

能力越强，权限越要清楚More capability demands clearer permissions

能写文件、跑命令、操作 Git 和浏览器的 Agent 必须有边界。权限策略、用户确认、沙箱和审计是核心能力，不是事后补丁。An agent that writes files, runs commands and drives Git and a browser must have boundaries. Permission policy, confirmation, sandboxing and audit are core features — not afterthoughts.

04

桌面应用应该服务真实工作流A desktop app should serve real workflows

优先支持本地工作区、文件、终端、GitHub、浏览器、MCP 和长期运行。不是纯网页聊天，也不是只服务 demo 的玩具。Local workspaces, files, terminal, GitHub, browser, MCP and long-running goals come first. Not a web chat toy built for demos.

安全与隐私Security & Privacy

本地优先，边界清楚Local-first, with clear boundaries

会话、技能、记忆和配置默认保存在本机。模型请求只发送到你自己配置的服务商。Sessions, skills, memories and config stay on your machine by default. Model requests go only to the provider you configure.

技术架构Architecture

Rust 构建，模块清晰Built in Rust, cleanly modular

13 个职责分明的 workspace crate。全工作区禁用 unsafe（仅 OS 沙箱层例外并有审计说明），核心路径覆盖近 300 个单元测试。13 workspace crates with clear responsibilities. `unsafe` is forbidden workspace-wide (audited exception: the OS sandbox layer). Nearly 300 unit tests cover the core paths.
